# Eternal Terminal integration research

Research date: 2026-10-24. This document scopes [issue #8](https://github.com/mihazs/lazysh/issues/8); it does not claim that lazysh implements ET. Existing SSH work is in [PR #22](https://github.com/mihazs/lazysh/pull/22). Evidence below distinguishes inspected artifacts/source from implementation recommendations and untested behavior.

## Released protocol boundary

Release 7.0.0's [`Headers.hpp`](https://github.com/MisterTea/EternalTerminal/blob/7656a32a5bc15c6746726a27a5a4ba1e468fab6e/src/base/Headers.hpp) declares wire **protocol version 6**. Its [`ET.proto`](https://github.com/MisterTea/EternalTerminal/blob/7656a32a5bc15c6746726a27a5a4ba1e468fab6e/proto/ET.proto) defines initial client-ID/version exchange, connection status, sequence headers and repeated catch-up packets. Product version and wire version must not be conflated.

The [`SSH bootstrap`](https://github.com/MisterTea/EternalTerminal/blob/7656a32a5bc15c6746726a27a5a4ba1e468fab6e/src/terminal/SshSetupHandler.cpp) starts `etterminal` as the authenticated user. It supplies a provisional 16-character ID and 32-character passkey, with the ID beginning `XXX`; the server returns the effective pair in an `IDPASSKEY:` record. lazysh can perform that exchange through its existing verified Rust SSH channel. A local `ssh` subprocess is unnecessary. Bootstrap output must be bounded and parsed strictly, with credentials excluded from errors/logs. The host needs `etserver` and `etterminal`; connecting must not silently install or reconfigure them.

[`SocketHandler.hpp`](https://github.com/MisterTea/EternalTerminal/blob/7656a32a5bc15c6746726a27a5a4ba1e468fab6e/src/base/SocketHandler.hpp) frames setup/recovery protobufs using a host-endian signed 64-bit length. This is little endian on the advertised desktop/mobile architectures. It allows up to 128 MiB; an embedded client should enforce a smaller documented budget before allocation. The interactive [`writer`](https://github.com/MisterTea/EternalTerminal/blob/7656a32a5bc15c6746726a27a5a4ba1e468fab6e/src/base/BackedWriter.cpp) instead uses a network-order 32-bit length. These are different framing layers.

An interactive [`Packet`](https://github.com/MisterTea/EternalTerminal/blob/7656a32a5bc15c6746726a27a5a4ba1e468fab6e/src/base/Packet.hpp) has an encrypted flag, a type byte and payload. The released [`CryptoHandler`](https://github.com/MisterTea/EternalTerminal/blob/7656a32a5bc15c6746726a27a5a4ba1e468fab6e/src/base/CryptoHandler.cpp) uses libsodium secretbox with a 32-byte key, a 24-byte counter nonce and separate direction values. It increments the nonce before each packet. [`ETerminal.proto`](https://github.com/MisterTea/EternalTerminal/blob/7656a32a5bc15c6746726a27a5a4ba1e468fab6e/proto/ETerminal.proto) defines terminal bytes, resize metadata, initialization and forwarding messages. A terminal-only first implementation still needs initialization, keepalive and resize semantics.

## Reconnect and cold recovery

The released [`ClientConnection`](https://github.com/MisterTea/EternalTerminal/blob/7656a32a5bc15c6746726a27a5a4ba1e468fab6e/src/base/ClientConnection.cpp) reconnects to `etserver`, sends the existing client ID, and expects returning-client status. [`Connection::recover`](https://github.com/MisterTea/EternalTerminal/blob/7656a32a5bc15c6746726a27a5a4ba1e468fab6e/src/base/Connection.cpp) exchanges received packet sequence numbers and missing encrypted packets. A reconnect preserves nonce/sequence history; replay buffers contain ciphertext, not just terminal text. [`BackedWriter.hpp`](https://github.com/MisterTea/EternalTerminal/blob/7656a32a5bc15c6746726a27a5a4ba1e468fab6e/src/base/BackedWriter.hpp) permits 64 MiB of recovery history and disconnected writes; mobile limits require explicit backpressure and an honest failure when required history has been discarded.

Current upstream master `7ee361a75fbb3e0900445b110188996fbe950823` adds optional challenge authentication, authenticated reset decisions, reset salts and retry-later status to [`ET.proto`](https://github.com/MisterTea/EternalTerminal/blob/7ee361a75fbb3e0900445b110188996fbe950823/proto/ET.proto). The [current protocol document](https://github.com/MisterTea/EternalTerminal/blob/7ee361a75fbb3e0900445b110188996fbe950823/docs/protocol.md) and [proof/key-derivation implementation](https://github.com/MisterTea/EternalTerminal/blob/7ee361a75fbb3e0900445b110188996fbe950823/src/base/CryptoHandler.cpp) describe this capability. Those fields are absent from the 7.0.0 release. Support should be tested separately, without treating development-only behavior as a released guarantee.

**Implementation inference:** do not restore a released-protocol session after process death by reusing its passkey with freshly zeroed crypto counters. Initial delivery can reconnect while its state remains in memory and create a fresh ET bootstrap plus multiplexer attach after a cold launch. True cold ET reattach needs a verified reset/rekey handshake or securely persisted complete state. A client must not silently fall back to legacy behavior after observing a challenge/reset capability.

## Embedding choices

| Candidate | Verified source facts | Integration implication |
| --- | --- | --- |
| Official C++ | [Apache-2.0 license](https://github.com/MisterTea/EternalTerminal/blob/7656a32a5bc15c6746726a27a5a4ba1e468fab6e/LICENSE); [CMake](https://github.com/MisterTea/EternalTerminal/blob/7656a32a5bc15c6746726a27a5a4ba1e468fab6e/CMakeLists.txt) defines static `et-lib` and `TerminalCommon`, with protobuf, libsodium, OpenSSL, zlib, logging and platform helpers. | No stable mobile C embedding API established. Extracting transport-only FFI and maintaining native builds is possible but comparatively broad; CLI entry points, subprocess bootstrap, process signals and terminal ownership must be bypassed. |
| [AArnott Rust client](https://github.com/AArnott/eternal-terminal-client/tree/6c3da110b4b9bb0a82b2c1f37343d51eaebe3d3d) | [MIT](https://github.com/AArnott/eternal-terminal-client/blob/6c3da110b4b9bb0a82b2c1f37343d51eaebe3d3d/LICENSE); binary-only Cargo target. `backed.rs`, `connection.rs`, `crypto.rs`, `packet.rs`, `proto.rs` separate transport from `ssh_setup.rs`/`terminal.rs`. Uses RustCrypto XSalsa20-Poly1305 and legacy protocol-6 handshake. | Strongest small Rust reference candidate for the released protocol; extract/adapt a bounded library with attribution, rather than executing its CLI. Current framing permits 128 MiB and does not implement upstream master challenge/reset capability. Mobile compatibility and official-server interoperability remain unverified. |
| [`etr`](https://github.com/l1a/etr) | The project describes its own QUIC transport and requires its matching `etrs` server. | It does not meet stock ET-server compatibility; similar product naming is not protocol parity. |

No dependency or implementation was added by this investigation. The smallest recommended path is an in-process Rust transport adapted from the MIT reference, checked against the pinned official release source and an actual official server. Use maintained crypto/protobuf libraries instead of inventing cryptographic primitives or guessing the wire format. Retain the verified SSH connection for lazysh's file/agent/preview operations. Initial ET support should reject configured SSH-only bastion routes rather than imply they automatically apply to a separate ET TCP socket.

## Native validation before claiming support

1. Cargo unit/integration fixtures derived from the exact official release: initial/recovery framing, secretbox vectors, direction counters, resize/initialization, partial reads, malformed lengths and insufficient catch-up history. Enforce limits before allocation and a bounded disconnected input queue.
2. A native Cargo integration test boots an official `etserver`/`etterminal` fixture on isolated loopback ports/FIFOs and uses lazysh's verified SSH bootstrap. Prove UTF-8 input/output, resize, wrong-key refusal, secret-free errors and clean cancellation. No user's existing ET service or agent socket is involved.
3. A Cargo TCP proxy deliberately interrupts transfers at frame boundaries and mid-frame. Prove reconnect preserves ordered input/output without duplication, counter reset or unnoticed loss. Test the released baseline and challenge-capable upstream separately; cross-replay, bad proof and bad reset-salt cases must fail.
4. Compile the library for Android ARM64, iOS ARM64/simulator, Windows, macOS and Linux. On actual mobile devices test sleep/wake, network changes, OS suspension and cold process launch separately; measure idle wakeups, memory and battery. A desktop binary run does not verify these properties.

**Unverified:** official-server execution, mobile compilation of either reference, device recovery, battery/performance and same-version binary behavior. The source/artifact evidence establishes a concrete implementation route, not completed ET parity.
