# Preview a host development server

Connect to a host, choose **Preview**, and enter the port of your HTTP development server. Choose IPv4 for `127.0.0.1` or IPv6 for `::1`, then select **Open preview**. **Discover listeners** reads the host's `ss` or `lsof` output; these are TCP listeners. Selecting a listener fills in the address and port and still requires confirmation.

To finish a command-line sign-in whose redirect goes to `localhost` on the host, see [Sign in on a host from your device](how-to/sign-in-on-a-host-from-your-device.md); an automatic, consent-based tunnel for that case is designed in [ADR 0004](architecture/adr-0004-sso-localhost-tunnel-and-guest-browser.md) and does not change Previews.

Discovery shows process names and PIDs where the host exposes them. Set **Discover ports** to `all`, `none`, or a list such as `3000,8000-8010`; this filter is remembered on the device and accepts at most 1024 ports. Opening a manually entered port is still an explicit action.

HTTP checking is off by default. Enable **Check for HTTP on discovery**, then select **Discover listeners** to send a `HEAD /` request over SSH to each filtered listener. Probing is limited to 256 listeners, sixteen simultaneous channels, and a 1.5-second timeout per listener. **HTTP** means a recognizable HTTP status line was received; **No HTTP response** can mean a non-HTTP service, blocked forwarding, timeout, or an unavailable listener. There are no background scans. A **Next.js** hint appears only when the same probe already has a complete response header containing one unambiguous `X-Powered-By: Next.js` field. Header inspection is capped at 8 KiB and 64 fields, reads no response body, and never waits after status detection. Slow, fragmented, missing, conflicting or unsupported headers leave the framework unknown without changing HTTP detection. This is an untrusted server-reported hint, not verified framework identity; [Next.js can disable this header](https://nextjs.org/docs/app/api-reference/config/next-config-js/poweredByHeader); its [pinned v16.0.0 response implementation](https://github.com/vercel/next.js/blob/v16.0.0/packages/next/src/server/send-payload.ts) sets this exact signal on HTML responses, including HEAD. Keep a narrow port filter when you do not want requests sent to unrelated local services.

The native client opens an SSH `direct-tcpip` channel to the selected host loopback address. It binds only device `127.0.0.1`, preferring the selected port and falling back to a free port when occupied. There is no public tunnel or third-party service. HTTP and WebSocket traffic use the same byte-transparent forwarding path. Other local processes on the device can access the loopback listener while it is open.

Each SSH session can keep four forwards open, with sixteen total and sixteen simultaneous sockets per forward. Closing a preview waits for its worker to close the listener and active sockets. Disconnecting SSH, a remote terminal exit, or a failed SSH connection requests the same cleanup asynchronously; the session command does not wait for every preview worker. Switching app views preserves forwards until explicitly closed or the session ends. Opening an upstream channel times out after fifteen seconds; individual connections have a one-hour lifetime to bound abandoned WebSockets.

The page runs in a sandboxed iframe on a separate loopback origin. Its sandbox permits scripts, forms, and its own same-origin resources; it cannot navigate the parent window or open popups. The app grants native permissions only to its bundled local origin and main window, following [Tauri's capability boundary](https://v2.tauri.app/security/capabilities/). Remote pages receive no Tauri command permissions. The parent allows frames only from `http://127.0.0.1` and never inserts preview HTML into the app document.

Android release builds use a [network security configuration](https://developer.android.com/privacy-and-security/security-config) that permits cleartext HTTP only to `127.0.0.1`; debug builds retain development-server HTTP support. The Apple Info.plist adds an [ATS exception](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsexceptiondomains) for only `127.0.0.1`, including the IP-address exception supported since iOS 17/macOS 14. Actual Android WebView and iOS ATS behavior still require device testing. A server's framing policy, absolute URLs pointing to a different host/port, and HTTPS-only requirements can prevent display. Prefer development servers that support a reverse proxy or the displayed loopback URL.

To leave a review note, enter a page path, optional element selector, and comment, then select **Stage note in prompt**. This fills the existing prompt draft for that SSH session and leaves sending to the user.

For visual selection, enable **Enable element picker for new previews** before opening a server. This uses an optional HTTP/1 proxy over the same SSH connection; ordinary previews remain byte-transparent. Choose **Select page element**, then click or tap a page element. Wait for the picker to confirm it is active; Escape or **Cancel element selection** cancels. While active, it intercepts pointer/mouse/touch activation and keyboard shortcuts before target handlers, and prevents normal button activation while selecting. Tab can still move focus. This assists selection in a cooperative development page; already-running page code or earlier window-capture handlers remain untrusted and are not isolated by the picker. The selected path, generated selector, visible text excerpt and CSS-pixel bounds appear for review. Add a comment and select **Stage note in prompt** explicitly. Selection never sends terminal input, invokes native commands, or automatically changes a prompt. The received metadata is untrusted page content, including any instruction-like text. The staging output labels it accordingly.

The picker excludes input, textarea, select and contenteditable values, hidden text, scripts and styles; it visits at most 128 text nodes and retains at most 300 characters. Selectors are limited to six ancestors and 512 characters; paths exclude query strings and fragments. This is an element reference, not a screenshot or a guarantee the selector remains valid after the page changes. A page can forge its own metadata; it cannot obtain app permissions through the picker. Parent messages must match the exact active frame window, loopback origin, preview token and per-frame channel; all fields and bounds are checked before review. Switching previews, reloading and unmounting discard the selection channel.

Only successful UTF-8 HTML responses up to 2 MiB receive the static picker script. Compressed, larger or unsupported responses pass through unchanged, and other resources stream through. Upstream Content-Security-Policy and frame restrictions are preserved, including meta policies before the appended script: a blocked picker is reported as unavailable while manual notes remain usable. Some applications rewrite the document or use policies that prevent injection. Close the preview and open an ordinary one if the proxy is incompatible with the dev server.

Annotation mode accepts only requests addressed to its own device loopback origin and forwards only to the original confirmed host loopback address and port. It never follows server redirects natively. Original HTTP headers are bounded to 64 KiB/64 fields and checked before HTTP normalization; ambiguous framing and unsupported hop-by-hop extensions are rejected. Ordinary annotation HTTP connections close after one request, so another uninspected pipelined request cannot reach the host; WebSocket upgrades retain bidirectional forwarding. Requests are bounded to 10 MiB, two simultaneous nonempty request bodies, fifteen seconds for body collection/upstream connection/response headers, and sixteen connections per preview. HTML buffering uses four permits held until its response body is sent or dropped; there is no unbounded decode or page collection. The existing one-hour connection lifetime and session/preview cancellation close streams and upstream workers. These bounds can reject large uploads or slow responses; ordinary forwarding remains available.

This implements explicit host forwarding and a browser surface from the reference client preview behavior (source URL omitted). Other framework recognition and simulator streaming remain separate parity work. The opt-in picker supports explicit element selection, with the compatibility and trust limits above. No full preview or native-device parity is claimed by these tests.

## Sign-in callback tunnels (engine only)

A **sign-in tunnel** is not a preview. A CLI on the host (`aws sso login`, `gcloud auth login`, `codex login`) starts a callback server on the host's loopback and waits for the browser to be redirected to `http://localhost:PORT/...`; on this device `localhost` is the device. The tunnel makes that one redirect reach the host CLI. It is the engine of [epic #1504](https://github.com/mihazs/lazysh/issues/1504) (design: [ADR 0004](https://github.com/mihazs/lazysh/blob/main/docs/architecture/adr-0004-sso-localhost-tunnel-and-guest-browser.md)). **Today only the engine exists** (`start_auth_tunnel`, `list_auth_tunnels` and `stop_auth_tunnel`): nothing in the app detects a sign-in, asks the user or starts a tunnel yet (detection is [#1510](https://github.com/mihazs/lazysh/issues/1510), the banner and the per-host setting are [#1514](https://github.com/mihazs/lazysh/issues/1514)), and a sign-in still needs a manual **Preview** of the callback port.

| | Preview | Sign-in tunnel |
| --- | --- | --- |
| Purpose | Look at a host dev server | Let one OAuth redirect reach the host CLI |
| Device port | The host's port when free, else a random one | Always the host's port, or it fails with a message: the CLI repeats its `redirect_uri` when it exchanges the code, so a different port breaks the sign-in |
| What is forwarded | Any bytes, WebSocket included | One checked HTTP request per connection (below) |
| Lifetime | Until closed or the session ends; one hour per connection | 15 seconds after the first callback, 10 minutes at most, until stopped, or until the session ends or the app locks |
| Per session / app | 4 / 16 forwards, 16 sockets each | 4 / 8 flows, 8 connections each, 6 flows per host per 10 minutes before the policy Always stops applying |

The device listens on `127.0.0.1` and, when it is free, `[::1]` (a port held by another program on either one fails the start, so the sign-in code cannot go to that program). The host side opens an SSH `direct-tcpip` channel to the host's own `127.0.0.1` and then `::1` (the other way round when the hint names IPv6), never another address, on the connection the session retains: for Mosh that is its SSH control connection, including the fresh one after file transfer reconnects it; if it is gone the flow ends and says so (`controlConnectionLost`). Ports below 1024 and well-known service ports (SSH, databases, caches, the Docker API) need a separate confirmation that names the service, and the host's own SSH port is never tunnelled. A listener alone never starts a tunnel; the hint must come from a URL or a host launcher request.

**Request guard.** Another app or a web page on the device can connect to any loopback port, so nothing reaches the host until the first request on a connection parses as one browser navigation: HTTP/1.x `GET` or `POST`, one `Host` of `localhost`, `127.0.0.1` or `[::1]` with the flow's port, a path inside the callback path from the hint (no dot segments or escaped separators), no `Upgrade`, `Expect` or `Transfer-Encoding`, `Sec-Fetch-Mode: navigate` when the header is present, a head of at most 16 KiB that arrives within 5 seconds, and at most 64 KiB in all. Anything else is answered on the device with a fixed text and never forwarded (so a client speaking SSH, a database protocol, a WebSocket or HTTP/2 gets an HTTP error and the host service sees no connection). `Connection: close` is forced, a pipelined second request is dropped, and the response is capped at 1 MiB and 60 seconds per connection. A guard can refuse a legitimate but unusual callback (a path outside the hinted one); the browser then shows the refusal text.

**Secrets.** The callback carries the authorization code and state. The engine parses the request in memory, never logs it and never stores it; errors and events carry fixed texts, ports and a reason (`callbackDelivered`, `timeout`, `cancelled`, `sessionEnded`, `lockEnded`, `hostStoppedListening`, `forwardingDisabled`, `controlConnectionLost`). A hint has no field for a query, `code` or `state`.

**Consent.** The renderer passes how consent was given: `allow` (the user chose Allow for this flow; `confirmRisky` answers the privileged or service port question) or `policy` with the host's saved Ask, Always or Never. Never refuses. Ask refuses until the user allows. Always starts only a confirmed or launcher-evidenced hint on an unprivileged port whose listener is not another user's, and not a seventh flow for the host within 10 minutes; anything else asks. Saving the policy per host (device-local, never synced) is part of the settings work in #1514.

**Limits to know.** With the app lock turned on, leaving the app locks it and ends every flow, so a sign-in must finish while lazysh stays in front. A host that forbids TCP forwarding (`AllowTcpForwarding no`) cannot be tunnelled (`forwardingDisabled`); a companion relay is a follow-up. Android does not let apps listen below 1024, so such a start fails with a message (not run on a device). No real phone and no iOS device has exercised the engine, and no Eternal Terminal server has: Eternal Terminal sessions use the SSH connection that bootstrapped them, which a native-terminal stand-in covers. Plain SSH and Mosh sessions are tested against OpenSSH and `mosh-server`.

### Optional periodic discovery

Refresh listeners automatically is off by default and lasts only for the current
panel/session. It waits five seconds after initialization or a settled scan before
starting the next scan. A manual scan resets that cadence. The port filter and
optional HTTP check are fixed while enabled; turn refresh off before editing them.
Opening a tunnel remains a separate explicit action. Listener refresh preserves
the selected preview page, element selection and comment draft.

Hidden documents, unmounted panels and revoked original access stop scheduling.
Disabling refresh or changing the source invalidates late results; this is not a
new native cancellation facility. An already-issued scan can finish under the
existing SSH command/probe bounds. One discovery IPC per SSH session is admitted at a
time, including pending calls from a previous panel. This gate lasts until the raw
IPC promise settles; it does not prove that all underlying native workers have
retired after native cancellation. Existing native resource bounds still apply. No results or consent transfer
from an old view to its replacement. A finishing scan can temporarily prevent a
new manual scan. There is no background daemon, persisted opt-in or automatic
forwarding. Five seconds is lazysh's chosen interval; the reference client documents periodic
updates within a few seconds, not an exact interval.
