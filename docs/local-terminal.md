# Local desktop terminals

[Issue #25](https://github.com/mihazs/lazysh/issues/25), implemented in the [PR #24 stack](https://github.com/mihazs/lazysh/pull/24), tracks the desktop local-host terminal.

Choose **Open local terminal** in Hosts, or **Local terminal · this device** in the connection picker. This explicitly starts the current desktop user's default shell in their home directory. It inherits the native app's environment and has that user's ordinary filesystem and process permissions. No localhost SSH server, credentials, network listener or fabricated host identity is involved. Mobile builds report that local terminals require the desktop app.

Local sessions use the existing terminal input, UTF-8 display, selection, search, clipboard, keyboard and dictation composer. The session is labelled **Local PTY**. **Files**, **Diff**, **Attach**, **Preview** and **Devices** work on this device (see [Files and repository review](#files-and-repository-review), [Attachments and previews](#attachments-and-previews) and [Devices on this device](#devices-on-this-device)). Agent queries, usage reports, Apple host status and the notification inbox work for a local session when the target reports the companion (see [Agents board, transcripts, usage and notifications](#agents-board-transcripts-usage-and-notifications)); remote multiplexer tools are unavailable for local sessions. Terminal I/O routes through a separate local registry; SSH-only bridge helpers reject local session IDs. The planned parity work that lifts the remaining limits is specified in [Local workspace](local-workspace.md).

## Agents board, transcripts, usage and notifications

When `local_capability` reports `tools.companion` for the `default` target, a local session shows the same companion views as a host: **Agents** (the board, approvals, companion settings and hook setup), **Transcript** (Chat), **Usage** reports and **Apple status**, and the notification inbox includes it. The companion runs on this device from `lazysh-agent` as argv, with no SSH (see [local workspace](local-workspace.md#local-companion)), so the setup section offers no SSH install and says where `lazysh-agent` is looked up. Reports group under **This device**; every local tab on the target shares the host key `local:default`, so the board archive is shared and the inbox polls the companion once per target, not once per tab. A target that does not report the companion hides these views, and the session details say that `lazysh-agent` was not found on this device. The Agent view, the Herdr navigation and the multiplexer tools are separate slices (#1133, #1131).

## Files and repository review

`local_capability` reports a `default` target with its `tools`: `files` on every desktop build and `repository` when `git` (`git.exe` on Windows) is on the `PATH` local commands receive. The views a local session shows come from that list, so **Diff** stays hidden without Git.

Host tools resolve a session through one host context (`host.rs`). For SSH sessions it calls the existing SFTP and SSH command code. For a `local:` session it requires an adopted, live local terminal and ties every operation to it: closing the terminal, locking the app or exceeding the 30-second deadline ends the operation with `disconnected`, `app_locked` or `timeout`, and the command's whole process tree is killed and reaped (a process group on Unix, a kill-on-close job object on Windows).

- Commands run from argument lists, never a shell, `cmd.exe` or PowerShell string, with stdin closed and no console window. Arguments containing `&`, `%`, `"` or `$`, such as file names, reach Git unchanged. Children run in the home directory, so relative paths mean the same as over SFTP, and `TMUX`, `ZELLIJ`, `ZELLIJ_SESSION_NAME`, `HERDR_SESSION`, `HERDR_SOCKET_PATH`, `ENV` and `BASH_ENV` are removed.
- On Linux and macOS, children receive the login shell's `PATH`, read once per app start by a fixed `$SHELL -lc` probe without any interpolated text; a desktop-entry start often lacks the `~/.local/bin` or version-manager directories a terminal has. If the probe fails within 5 seconds, the app's own `PATH` is used. Windows uses the process `PATH`.
- Files use `std::fs` with the remote limits: 10,000 entries or 2 MiB of names per directory and a 1 MiB UTF-8 text preview. Reads refuse symbolic links and other non-regular files (`not_regular_file`); on Unix the open also uses `O_NOFOLLOW`. On Windows only drive paths are accepted; UNC and device paths are refused, for repository and **Diff** directories too, before Git starts (so Git never opens an SMB share).
- Repository review runs the same `git` arguments as on a host (`GIT_OPTIONAL_LOCKS=0`, `--literal-pathspecs`, no external diff or text conversion). Historical files are read as raw `git cat-file` bytes; the SSH arm keeps its `od` encoding, its error messages and kinds. Over SSH every argument outside `[A-Za-z0-9-_./:,+@]` is single-quoted, so a name such as `=1.0` is not expanded by zsh.

## Companion on this device

The native companion commands (`agent_snapshot`, `agent_usage`, `agent_transcript`, `agent_transcripts`, `agent_reported_history`, `agent_history`, `agent_approvals`, `resolve_agent_approval`, `get_companion_settings`, `update_companion_settings`, `get_host_browser_settings`, `update_host_browser_settings`, `get_notification_policy`, `update_notification_policy`, `companion_hooks`, `companion_hook_discovery` and `notify_agent_attention`) resolve a `local:` session through the same host context, so the Agents board, approvals, transcripts, settings, hook setup and notifications can serve this device. The interface still hides them for local sessions until the interface slice of [#1132](https://github.com/mihazs/lazysh/issues/1132) ships; `local_capability` reports `tools.companion` for the target meanwhile.

- Nothing is probed or installed over SSH. The command builders keep their one-line form; a local session splits that line back into arguments (bare safe words and single-quoted text only, anything a shell would interpret is refused as `companion_command`) and runs the companion as argv, never through `sh`, `cmd.exe` or PowerShell. A transcript path such as `x'; touch pwned; '` is one argument of `lazysh-agent`.
- The executable is chosen, best first, as the `lazysh-agent` beside the app executable (where the desktop bundle puts it), then the managed copy at `<data>/lazysh/companion/lazysh-agent` (the location the remote installer uses; it must be a regular executable of the current user that nobody else can write, and is not used on Windows), then the first absolute `PATH` entry that has one. With none, the command fails with `remote_command_failed` and "lazysh-agent is not available on this device".
- The companion runs with the desktop user's own account, home and agent profiles. Hook setup (`lazysh-agent hooks install`) writes the local user's agent profiles on Linux and macOS and binds the hooks to the companion executable's own path. The companion bundled beside the app can sit on a path that does not outlive the app (an AppImage runs from a temporary mount), so hook setup (status, install and remove, which must run the same executable because the plan covers its path and file) first places a copy of the bundled companion at the managed path, owner-only (`0700`) in a directory nobody else can write, written to a new file and renamed into place. It keeps a managed copy that is the user's own, not a link and at least as new as the bundled version, and replaces an older or unreadable one; the hooks then call the managed copy, which keeps working after the app is gone. Discovery and every other command keep running the bundled companion. A companion found at the managed path or on the `PATH` is used as it is. On Windows the companion reports template-only hook setup (`supported: false`) until [#490](https://github.com/mihazs/lazysh/issues/490); Herdr's agent detection supplies state there.
- Remote companion resolution, installation and every remote command string are unchanged.

Uploads from **Files** stay an SSH host tool; the button is hidden in local sessions.

## Multiplexer commands (native layer)

The native multiplexer commands `multiplexer_tree`, `multiplexer_sessions`, `list_multiplexer_sessions`, `tmux_action`, `zellij_action` and `zellij_tabs` resolve `local:` session ids through the same host context. The app does not offer them in a local session yet: **Sessions**, **Jump To**, the toolbar and the Herdr views stay hidden until the interface slice of [issue #1131](https://github.com/mihazs/lazysh/issues/1131) lifts those gates. SSH sessions behave as before.

- Discovery replaces the remote `command -v` script with a lookup on the `PATH` local commands receive, then runs `tmux -V`, `herdr --version` and `zellij --version` and, when a tmux server answers `has-session`, `tmux list-panes -a`. The reply feeds the parser the remote script feeds, so the tree and the version support levels are identical. tmux is never reported on Windows: there is no native Windows tmux, and it is reached through a WSL target.
- Herdr is looked up on the `PATH` first and then in `~/.local/bin`, where the official installer puts it. The fallback applies only when the whole path is owner-controlled (the `herdr` file is a regular file owned by the user with one link and no group or other write bit, and every directory up to `/` belongs to the user or to root, with shared ones only as root-owned sticky directories like `/tmp`; symbolic links are refused). This is the check the remote `herdr_path` script runs, done with `std::fs`; a test runs both on the same cases and requires the same verdict. Windows has no such fallback.
- Actions are argument lists. A session name, a window title or a directory containing spaces, quotes, `$(...)`, `#`, a trailing `;` or a leading `-` reaches tmux and Zellij as exactly one argument. Over SSH the same argument list is rendered into one command line, quoting every word outside `[A-Za-z0-9-_./:,+@]`; a word made only of those characters, such as the tmux server name `default`, is no longer quoted.
- The `tmux_server` choice names a server with `-L`, as over SSH. A local terminal attached to a tmux server (see [Attaching a multiplexer session](#attaching-a-multiplexer-session)) keeps to it: a request for another server is refused, as over SSH.

## Attachments and previews

`local_capability` reports `attachments` and `previews` for the `default` target on every desktop build, so a local session offers **Attach** (the workspace tool, the terminal's Attach key and the composer's Attach action) and **Preview**. Both go through the same host context as Files. Every other native Windows shell shares them; a WSL target reports neither and refuses both (`remote_command_failed`), because they would write to or reach a port of Windows, not of the distribution.

- **Attachments.** An upload creates a new file on this device and never replaces one: a `create_new` open fails when anything, even a dangling symbolic link, already has the name (`file_exists`). The default is a private, uniquely named `lazysh-<random>-<name>` file, as on a host: in `/tmp` on Linux and macOS, opened `0600` and checked to be owner-only before any byte is written (a filesystem that ignores the mode is refused with `upload_not_private` and the empty file removed), and in the per-user `%TEMP%` directory on Windows, whose ACL already excludes other accounts. An explicit destination is an absolute path or a path relative to the home directory, with no control characters. The 10 MiB limit, the two-uploads-at-a-time reservation and cancellation are shared with SSH sessions. The returned path uses `/` separators (`C:/Users/you/AppData/Local/Temp/lazysh-…`) so one terminal paste rule covers every host. **Paste uploaded path** and **Add to composer** use that local path as before. There is no host clipboard to copy to, so the **Copy raw path on Mac host** action is hidden; **Copy host path** uses this device's clipboard.
- **Preview discovery.** **Discover listeners** runs `ss -H -ltnp` (or `lsof -nP -iTCP -sTCP:LISTEN -F pcn` when `ss` is not installed, as on macOS) on Linux and macOS and `netstat -ano` on Windows, as argument lists, and parses the output in Rust. Windows localizes the state word, so a listener is a `TCP` row whose foreign port is 0; its IPv4 and IPv6 rows both appear. Windows reports the owning process id, not its name. The list is capped at 256 entries and the same loopback and wildcard filter applies as over SSH.
- **Opening a preview.** **Open preview** proxies a fresh `127.0.0.1` port to the dev server's loopback port through the existing relay or element-picker proxy. A local preview never takes the dev server's own port, which stays reachable; over SSH the preview keeps the host's port number when it is free so dev-server redirects keep working. Previews connect to `127.0.0.1` or `::1` only, at most four per session and sixteen in the app. Closing the local session, locking the app or choosing **Close preview** stops the proxy.

## Devices on this device

A local session shows **Devices** when `local_capability` reports `tools.devices` for its target: an Android SDK `adb` resolves where the companion looks for it (under `ANDROID_HOME`, else `ANDROID_SDK_ROOT`, when either is set, and only there; otherwise on the `PATH` local commands receive), or, on macOS, `xcrun` resolves on that `PATH`. Without either the view stays hidden, as **Files** and **Diff** do. Android works on Linux, macOS and Windows; iOS Simulators need macOS. Choosing the iOS platform on another system reports the missing SDK, as it does on an SSH host without one.

The view and its commands are the SSH ones. `list_devices`, `device_frame`, `device_action`, `android_device_probe`, `ios_device_probe`, `ios_device_action` and `device_stream_start` resolve a `local:` session through the host context and run `lazysh-agent devices …` on this device as argv, like [the companion](#companion-on-this-device); the companion runs `adb`, `emulator`, `xcrun simctl`, `idb` and `ffmpeg` itself, with the checks, bounds and deadlines described in [Host devices](devices.md).

- **Video** is a long-running companion child with piped stdin and stdout. Its output goes through the code the SSH arm uses (one JSON frame per line, validated for identity, size and dimensions, latest-frame slot, one stream per session, two overall, 180 s for Android and 900 s for iOS, 12 s without a frame). Stopping the preview, closing the session, or locking the app ends the child's stdin first, which makes the companion stop and reap the `adb` and `ffmpeg` it started; a companion that has not exited after 2 s is killed together with its process tree. Nothing is left running.
- The SDK runs with the desktop user's own account and `ANDROID_HOME`, as it does for any command typed in the terminal. Authorize the device's debugging key on this machine first; lazysh does not install SDKs, pair devices or start an adb server of its own beyond what `adb` itself does.

Workspace restore for local sessions follows in a later slice of [#1129](https://github.com/mihazs/lazysh/issues/1129).

Workspace restoration saves `{ "local": true }`, plus the `target` id when the session was not opened in the default shell (see [Choosing a target](#choosing-a-target)). Restoring starts a fresh local shell in that target after the explicit restore action; it cannot recover a terminated shell process, terminal output or working directory. Shell history follows the user's shell configuration, independently of workspace metadata.

To start one local workspace from a terminal, close existing lazysh instances and run:

```sh
lazysh --dir '/absolute/project directory'
lazysh -dir ./relative-project
```

`-dir=PATH` and `--dir=PATH` are also accepted. Paths are literal: lazysh performs no shell expansion, globbing or command interpolation. Relative paths resolve against the launching process's working directory and are canonicalized. The supplied and resolved paths must be valid Unicode and at most 4096 UTF-8 bytes. Invalid/missing directories, non-Unicode paths, Windows drive-relative paths such as `C:project`, duplicate directory options and combinations with other arguments fail before UI startup with exit 2. Saved-host cold launch is documented in [SSH connections](connections.md#cold-saved-host-desktop-launch); cold host/multiplexer picker composition is described there as well. Without an owned CLI option, framework flags and existing desktop URL handling retain their prior behavior.

Cold and warm directory launches keep the canonical path native in one bounded, non-overwritable intent. Its first protected read admits the request to that original access lease and returns its receipt once; only that lease may submit the receipt through the normal guarded local-connect command. Preparation failures do not retry automatically, and locking or replacing that lease before connect prevents a fresh renderer from replaying the old request. Manual local opens and workspace restoration do not claim it.

When an instance is already running, relative paths resolve against the secondary process's forwarded absolute working directory, never the running app's directory. Warm paths, and the caller directory when needed, must contain no Unicode replacement character (`U+FFFD`), even literally: the singleton transport cannot distinguish it from replaced OS bytes. Ambiguous conversions are refused with a localized notice after normal unlock; close the app and cold-launch to use a literal replacement character. A second valid request cannot replace an existing intent. The secondary process retains the singleton handoff exit behavior; a successful handoff is not confirmation of a directory terminal. Actual OS GUI launch acceptance remains tracked in issue #86.

On Windows, the canonical directory stays in native launch state. At PTY startup lazysh uses the already pinned `dunce` compatibility helper to simplify only safely representable names to an ordinary absolute drive path, then verifies that it canonicalizes to the same directory. UNC, device, verbatim-only and names/lengths that cannot safely simplify are refused with a localized error; a different shell is not selected automatically. The original hosted Windows trace showed `cmd.exe` rejecting a canonical verbatim drive prefix as UNC and falling back to `C:\Windows`; the compatibility correction must pass the actual default-shell cwd regression before Windows acceptance is claimed.

An explicitly requested directory never silently falls back to HOME. If it disappears before native process working-directory setup, startup fails. Filesystem changes after a child enters the directory follow OS semantics. Unix uses the selected login shell; user/system startup files can subsequently change directory, so this does not promise to override shell configuration. The launch mechanism does not serialize the directory into workspace metadata or launch-notification payloads. Restoration continues to use the normal HOME default.

Native regression tests cover parser bounds, caller-relative paths, literal shell-looking names, Unicode refusal without replacement, one-shot receipts, stale leases, actual login-shell `pwd`, and removal after validation. Windows has native drive/Unicode and actual ConPTY working-directory fixtures; executing those on a Windows runner remains a separate platform gate. Frontend tests cover deferred/fresh access, stale success/error suppression, localized warm notices, preparation failure without retry across busy transitions, raw sentinel-looking diagnostics remaining verbatim across locales, and unchanged manual/restoration calls. Source or component checks alone do not establish actual desktop GUI launch acceptance on every OS.

## Attaching a multiplexer session

`local_connect` accepts an optional `attach` entry, the typed entry the SSH `attach_multiplexer` command also takes: `{ kind: "tmux" | "herdr" | "zellij", name, tmuxServer?, createIfMissing? }`. Unknown fields are refused, and so is an entry combined with a launch folder. On Windows, Zellij (0.44 or newer) and Herdr (0.8.2 or newer) attach natively through the ConPTY; tmux has no native Windows build, so a tmux entry is refused there and a WSL target brings it ([issue #1663](https://github.com/mihazs/lazysh/issues/1663)). Without `attach` the command starts the default shell as before. The app does not offer the choice yet: the interface slice of [issue #1131](https://github.com/mihazs/lazysh/issues/1131) ([#1664](https://github.com/mihazs/lazysh/issues/1664)) adds it.

- The renderer names a session; it never supplies a program, an argument or shell text. The entry is validated natively with the SSH rules (tmux server names, Herdr names of 1-64 ASCII letters, numbers, periods, underscores and hyphens, Zellij names that do not begin with a dash) and becomes an argument list that the PTY starts directly, with no shell in between: `tmux -u -L <server> attach-session -t =<name>` (`new-session -A -s <name>` with `createIfMissing`), `herdr --session <name>` and `zellij attach [--create] <name>`. A name with spaces, quotes, `$(...)` or `#{...}` is one argument, and a tmux name that ends in `;` gets the escape it gets over SSH.
- The child gets the login shell's `PATH` and none of `TMUX`, `ZELLIJ`, `ZELLIJ_SESSION_NAME`, `HERDR_SESSION`, `HERDR_SOCKET_PATH`, `ENV` and `BASH_ENV`, so a lazysh started inside a multiplexer does not hit a nested-session refusal. Herdr is looked up on that `PATH` first and then in the owner-checked `~/.local/bin` fallback described above, for the PTY as for the host tools. On Windows the child gets the process `PATH`, and the program is found before the PTY starts: each `PATH` directory in order is tried with the name plus every `PATHEXT` extension that a process can be started from (`.com` and `.exe`, in `PATHEXT` order, or `.exe` alone when `PATHEXT` is unset), and the absolute path is what the ConPTY runs. Multiplexer discovery and one-shot actions find programs the same way, so a program that attaches is also listed and acted on. Relative PATH entries are anchored to the app's current directory before checking the file; this does not pin the executable against later replacement. A `.bat` or `.cmd` never resolves, since a batch file needs `cmd.exe` and its unsafe argument escaping. A program that is not found is named in the error (`zellij was not found on the PATH; install its Windows build`) instead of ending in a bare `CreateProcess` failure.
- Before the PTY starts, the same preflight the SSH attach runs checks the entry on this device, as argument lists with no shell: the tool answers `tmux -V`, `herdr --version` or `zellij --version`, and an attach (without `createIfMissing`) needs the session to exist (`tmux has-session -t =<name>`, the name running in `herdr session list --json`, or a live, not exited, name in `zellij list-sessions`). A missing tool, a failing version check or a missing session ends the call with `Cannot enter the selected multiplexer. Check that it is installed and the named session can be opened.` and starts no terminal. With `createIfMissing` only the version check runs, as tmux (`new-session -A`), Zellij (`attach --create`) and Herdr create the session themselves.
- The tmux display binding, the Herdr guard binding, the tmux server, the upload slot and the companion install semaphore live in one `Bindings` struct that both SSH and local sessions embed. For a local tmux attach the PTY child is the tmux client, so its process id and the PTY's terminal name identify the displayed client, with no `printf` handshake. A second child, `tmux -u -L <server> -C attach-session -f no-output,ignore-size`, carries the control stream over pipes and runs the same parser, budgets and admission checks as the SSH channel does. `tmux_jump_snapshot` and `tmux_jump` resolve `local:` ids. As over SSH, a control client that cannot be verified leaves the terminal without navigation; the attach itself stands.
- Herdr runs the guard here too. Before the attach, `herdr --session <name> api guarded` is asked the fixed probe SSH uses (an invalid preparation number, which only a guarded Herdr answers with exactly `guard_invalid`); only then does the PTY start `herdr --session <name> --guarded-attach`, and a Herdr that does not admit the guard stays an ordinary attach, as over SSH. The client opens its display with one private first frame (a ticket) on the PTY. The terminal's reader takes that frame off before any byte reaches the terminal, accepts it only as the very first bytes with the SSH framing and budgets, and never searches later output for a ticket; a stream that opens with anything else, or ends first, closes the terminal. The ticket is claimed once through a one-shot `herdr --session <name> api guarded` child (argument list, request on stdin, reply on stdout or stderr, three-second deadline, 32 KiB bound, the child and its tree end with the exchange). A claim that fails or is not confirmed closes the terminal; it never falls back to an ordinary attach. The same actor then serves `herdr_chat` for `local:` ids (`status`, `prepare`, `confirm`, `input`, `release`, `observe`, `scroll_history`), with the same receipts, operation numbers and access leases as over SSH, and ends with the terminal. Mosh's startup-descriptor receipt stays an SSH feature. `herdr_action` focus retirement and local Herdr discovery follow in [#1665](https://github.com/mihazs/lazysh/pull/1665).

## Choosing a target

`local_capability` lists the targets a desktop can open. Linux and macOS report one, `default` (the login shell), and show no picker. Windows reports `default`, which is `%ComSpec%` (usually `cmd.exe`), and every other shell it finds:

| Target id | Label | What starts |
| --- | --- | --- |
| `default` | `cmd` | `%ComSpec%`, as before |
| `pwsh` | PowerShell | PowerShell 7: `%ProgramFiles%\PowerShell\7\pwsh.exe`, else the first `pwsh.exe` on the `PATH`, started with `-NoLogo` |
| `powershell` | Windows PowerShell | `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe` with `-NoLogo` |
| `gitbash` | Git Bash | Git for Windows' `bin\bash.exe --login -i`, found under `%ProgramFiles%\Git`, `%ProgramFiles(x86)%\Git`, `%LOCALAPPDATA%\Programs\Git` or next to a `cmd\git.exe` on the `PATH`. `System32\bash.exe` is the WSL launcher and is never offered as Git Bash |
| `wsl:<distro>` | `<distro> (WSL)` | One per distribution in `wsl.exe --list --quiet`: `wsl.exe -d <distro> --cd ~`, the distribution's login shell in the Linux home |

The renderer sends an id, never a path or a command. `local_connect` detects the machine again and refuses an id it does not find (`That local terminal target is not available on this device`), so a saved id for an uninstalled shell or a removed distribution fails with that message and stays in the restore offer. Programs are launched as argv with the absolute path that detection found; the distribution name is its own argument.

A multiplexer `attach` entry always runs on this device's own shell: `local_connect` refuses one combined with a non-default `target` (`Multiplexer sessions attach on this device's own shell`) until tmux, Herdr and Zellij run inside a WSL target.

`wsl.exe --list --quiet` is read with a 5-second deadline and a 64 KiB bound, only when it exits successfully. Its output is UTF-16LE (a byte-order mark is accepted); a name must be 1 to 64 letters, digits, `.`, `_` or `-` and start with a letter or digit, at most 32 are offered, and anything else, such as the sentence it prints when no distribution is installed or a name with a space, is dropped.

With more than one target, **Hosts** shows a **Local terminal target** list under **Open local terminal**. The button and the command palette entry open the chosen target; a `--dir` launch always opens the default shell. A native Windows target shares this device's host tools (**Files**, **Diff**). A WSL target runs its own, described next. Terminal, voice and usage work. The session's destination reads `This device · <target label>`.

### Files and Diff inside a WSL target

The files and Git of a WSL session live in the distribution, so the host tools run there instead of on the Windows disk:

- **Commands.** Every host command (Git for **Diff**, and any other tool that runs argv on the host) starts as `wsl.exe -d <distro> --cd ~ -e <argv>` from the distribution user's home directory: argv only, no shell string, with the same 30-second deadline, 1 MiB output bound and process-tree cleanup as a native command. A command's constant environment (`GIT_OPTIONAL_LOCKS=0`) is passed as `env NAME=VALUE` arguments in front of the program, because `wsl.exe` does not forward the Windows environment by itself. The program is looked up on the distribution's own `PATH`, which is the non-login `PATH` of `wsl.exe -e`, not a login shell's.
- **Paths.** A WSL session names every path as a Linux path (`/home/me/project`), and the home directory is the distribution user's (`pwd -P` after `--cd ~`). **Files** reads and lists through `\\wsl.localhost\<distro>\...` with `std::fs` and the same caps (1 MiB previews, 10,000 entries, no following of links without confirmation) and no-follow checks as a native session; the path is built by appending components, so a component such as `C:` cannot replace the share. Accepted path forms: a Linux path, a `\\wsl.localhost\<distro>\` path of this very distribution (the host name and distribution compare without regard to case) and a Windows drive path, which `wslpath -u -a` turns into its Linux path (output that is not a clean Linux path is refused). Refused with `invalid_path` before anything runs: a relative path, `.` and `..` components, a backslash inside a Linux path, control characters, other UNC hosts (`\\server\share`), another distribution, `\\wsl$\...`, and device paths (`\\?\`, `\\.\`). A **Diff** or repository directory must be a Linux path, because Git runs inside the distribution. A symbolic link reports where it points as a Linux path of the distribution; a link that leaves it is refused.
- **Capability.** `local_capability` reports `files` and `repository` for a distribution only when `git --version` runs inside it (a 10-second deadline; every distribution is probed at once). The probe starts a stopped distribution, which WSL stops again once it is idle. A distribution without `git` shows neither **Files** nor **Diff**. `companion` stays `false`: the Windows `lazysh-agent` cannot serve a distribution, so the Agents board, approvals and hook setup report `lazysh-agent does not run inside a WSL target yet` for a WSL session.

Not covered yet: tmux, Herdr and Zellij and the companion inside a WSL distribution, and the **This device · <distro> (WSL)** label on the Agents board ([#1746](https://github.com/mihazs/lazysh/issues/1746)). A multiplexer `attach` combined with a non-default target is refused until then.

## Verification

Run `bunx moon run client-native:test-local`. This uncached task runs project-native Cargo tests with real processes. The `host::tests::local::` cases open a real local session and, through its host context, list and read files (bounds, UTF-8, binary and symbolic-link refusals), show staged, unstaged and untracked changes, history, a historical file and diffs in a temporary Git repository with `&`, `%`, `"` and `$` in names, messages and pathspecs (Windows passes `"` as a pathspec, since NTFS names cannot hold it), refuse UNC and device repository paths on Windows, cancel a running command by closing the session, and time out a command and confirm its process is reaped. The attachment and preview cases create two private uploads and prove they are distinct, owner-only and never overwrite an existing file, a dangling link or a name that is in use, then run discovery against real IPv4 and IPv6 listeners (`ss` or `lsof` on Linux, `netstat` on Windows), open two previews of a local HTTP server and fetch its page through each, stop one, and close the session to stop the other. The `chmod` refusal is checked by a controlled simulation of a filesystem that ignores it, because no such filesystem is mounted on the test hosts. They run on Linux in `native-linux-runtimes` and on Windows (`git.exe`, drive paths) and macOS in `native-desktop`. The Linux native GUI suite opens **Files** and the diff of a modified file from a local session. Linux tests cover executed UTF-8 input/output, `stty` resize, independent sessions, forged acknowledgment rejection, output-credit exhaustion/resumption, stalled-consumer cancellation, owned-process reaping, failed-spawn teardown and state-drop cleanup. A stopped window refuses new PTYs; registration checks the same shutdown flag again under the registry mutex.

Two ignored cases, `multiplexer::tests::real_local_session_discovers_tmux_and_applies_actions_with_literal_names` and `zellij::tests::real_local_session_lists_zellij_sessions_and_switches_tabs`, run in `native-linux-runtimes` with `test:multiplexers`, and the workflow counts them with `--list --ignored`. Each opens a real local session whose host-tool commands see a temporary `HOME`, `XDG_*` and `TMUX_TMPDIR`, so no test touches the user's own tmux, Zellij or Herdr. The first discovers a real tmux server by its unique `-L` name, creates a session whose name holds spaces, both quote kinds, `$(...)`, `#(...)` and a trailing `;`, runs the split, zoom, select, window and rename actions and reads each result back through `multiplexer_tree` and `list_multiplexer_sessions`. The second lists a Zellij session, creates a tab with a hostile name and directory, and checks that `GoToTab`, `NextTab` and `PreviousTab` move the active tab `zellij_tabs` reports. Herdr trees and actions and the Windows cases are not covered yet.

The stream cases of the same group (`host::tests::local::`) hand out a local command's output in chunks and report whether it ended cleanly or with a failing exit, and remove a stream's child on close or drop even if it ignores the end of its input. The companion cases (`companion::local::tests::`, run by `native-linux-runtimes`, and by the macOS and Windows desktop jobs) drive the real `lazysh-agent devices` commands on a local session against a fake Android SDK (`apps/agent/examples/fake_android_sdk.rs`, standing in for `adb`, `emulator` and `ffmpeg`): a device listing, a screenshot, the video probe, frames from a running stream, and that stopping the stream or closing the session removes the `adb` and `ffmpeg` processes it started. The fake is not a device: real Android video and input and iOS Simulators are not covered by these cases.

The macOS/Windows desktop CI jobs execute the task after building. Windows cases run a real ConPTY shell, send UTF-8, resize, test credit backpressure/cancellation, and query the owned PID after close, list `cmd` and the installed PowerShells as targets and print `$PSVersionTable.PSVersion` from each detected PowerShell target. Target detection and the `wsl.exe` listing parser run with fakes and UTF-16LE bytes on every platform; the WSL host tools run on every platform against a stand-in `wsl.exe` script that checks the argument shape, runs the command from the home directory and answers `wslpath` (`host::tests::local::wsl::`): argv and environment, listing, reading and a Git diff, the path validation above and the `git` probe. The cases that start a real WSL distribution (the login shell, and `local::tests::real_wsl_target_reads_a_file_and_shows_a_diff_through_the_host_context`, which reads a file through the UNC share and shows a diff) are ignored, because hosted runners have none, and stay unverified until a machine with WSL runs `cargo test --lib local::tests::real_wsl -- --ignored`. Unsupported environments fail with their actual startup diagnostic rather than reporting a passing PTY test. macOS/Windows runtime results remain pending until those CI jobs execute; compilation on Linux does not establish their behavior.

Four ignored cases, `local::attach_tests::runtime::real_local_attach_*`, run in `native-linux-runtimes` with `test:multiplexers`, and the workflow counts them with `--list --ignored`. Each attaches through `desktop::connect` with a temporary `HOME`, `XDG_*`, `TMUX_TMPDIR` and `ZELLIJ_SOCKET_DIR`, so none touches the user's own tmux, Zellij or Herdr. The tmux cases attach a session whose name holds a space and both quote kinds and check that output reaches the session's events; jump to a second session through `tmux_jump` and confirm with `display-message -c <tty>` on the same server that the displayed client moved; create a missing session only with `createIfMissing`; and refuse a missing one without it before any terminal starts. The Herdr case attaches stock Herdr, sees the alternate screen and reads the session's snapshot through `herdr --session <name> api snapshot`. The Zellij case creates a session whose name holds a space and quotes and finds that exact name in `list-sessions`. The unit cases cover the argument lists, the refusal of unknown fields and the invalid names, and a real PTY shows that the identity names the child and the terminal printed by `tty`. Three non-ignored cases drive `desktop::connect` against a scripted `herdr` on the test's PATH: the guarded attach keeps the first frame and its secrets off the terminal, binds the guard and runs only the guarded attach; a claim the host does not confirm closes the terminal and runs no ordinary attach; a Herdr that rejects the guard subcommand stays an ordinary attach with no guard. Always-run cases with stand-in `tmux`, `zellij` and `herdr` scripts on a private `PATH` check that a missing tool, a failing version check, a missing tmux session, a Herdr session that is listed but not running and a Zellij session that is exited or unlisted are refused before any terminal starts, that an existing one reaches the PTY as exactly the argument list above, that `createIfMissing` runs no existence check, and that a Herdr in the owner-checked `~/.local/bin` starts when it is not on the `PATH`. Unit cases cover the reader that takes the first frame off a display in any split (including a frame that ends exactly where a read does), its refusal of a late, oversized or missing frame, and the one-shot exchange (argument list with a hostile name, request on stdin, refusals with their meaning, the reply budget, the deadline that ends the child, and the exact probe that admits the guard). One more ignored case, `guarded_herdr_input_on_a_local_pty_reaches_only_the_confirmed_pane`, runs in `native-linux` with the same run's guarded build as `LAZYSH_TEST_HERDR`: it starts an owned guarded server with a workspace, attaches it through `desktop::connect`, checks that the first frame never reaches the terminal, prepares and confirms a pane that records its input, sends text and Escape through `herdr_chat` and reads exactly those bytes back, sees a dialog answer, a spent operation number and a released receipt refused with nothing reaching the pane, and sees the guard end when the terminal closes. It is not part of `test:multiplexers`, which has no guarded Herdr. The Windows cases are not covered yet.
