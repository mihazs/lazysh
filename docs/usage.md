# Recorded token usage

The Usage view inspects counters from an explicitly selected host transcript over its existing SSH connection. Collection runs only when you inspect, refresh, or request the next records. It does not read provider credentials, contact a billing endpoint, or enable background collection.

```sh
lazysh-agent usage --agent claude --path /absolute/path/session.jsonl --offset 0
lazysh-agent usage --agent codex --path /absolute/path/rollout.jsonl --offset 0
lazysh-agent usage --agent opencode --path /absolute/path/opencode.db --session-id ses_selected --offset 0
```

The command reuses the supported [transcript adapters](companion.md), their file/database validation, and their opaque cursors, with a dedicated Codex token-count event reader described below. It examines one bounded window of at most 100 normalized transcript records (100 token-count events for Codex) and returns the last 20 usage samples within that window. `nextOffset` and `hasMore` let the caller inspect later records. The first window is not necessarily the newest part of a large transcript. A source with no counters returns an empty sample list; absence is not zero consumption.

The response has `schemaVersion: 1`, `scope: "transcript_window"`, `agent`, `observedAt`, `nextOffset`, `hasMore`, `samplesAvailable`, `samples`, `context`, and `quota`. Each sample has a source record `id`, optional `recordedAt`, `freshness`, and nullable `inputTokens`, `outputTokens`, `cacheReadTokens`, and `cacheWriteTokens`. `samplesAvailable` counts distinct records with recognized counters in this window, before the 20-sample display limit. Missing counters remain JSON `null`; an explicitly recorded zero remains zero. Counter values outside JavaScript's safe nonnegative integer range are rejected.

Counters are **never added together**. Streaming assistant records can repeat the same provider request's usage across several content blocks. Different providers also account for cache tokens differently. Exact repeated record IDs keep their last report within the inspected window, but different IDs are not assumed to identify different billable requests. No total cost, cumulative consumption, or remaining allowance is inferred from these samples.

`observedAt` is when the host inspected the records. `recordedAt` is the transcript's message/event timestamp when present and parseable; a recently modified file does not establish a fresh counter. A report older than 15 minutes is labeled stale. Missing or future report times have unknown freshness. The client also ages displayed reports without fetching more data, using elapsed time since receipt plus the host's reported age. Refresh updates the inspected window; it does not make an old report fresh.

Live context used, context window size, context remaining, provider quota and quota reset remain unknown (`context` and `quota` keep their original nullable fields). A recorded input-token count is not proof of current live context or remaining account capacity. Additive optional fields `recordedContext` and `providerWindows` expose the verified Codex records described below. Older schema-1 responses without these fields remain supported. Usage samples do not establish which agent or account is currently running in the selected terminal.

## Recorded Codex context and provider windows

For `--agent codex`, usage reads `event_msg` records whose payload type is `token_count`. The reader examines up to 4 MiB, accepts complete JSONL records up to 256 KiB, and stops after 100 token-count events. Its byte cursor advances across ignored records and retries an incomplete trailing record on refresh. It uses the transcript reader's regular-file, no-follow and Unix-owner checks. File identity/truncation changes, and same-size modification-time changes detected during reading, fail for a fresh retry; appends can be inspected in later windows. It returns only recognized numeric/time/limit metadata, never prompt content or provider credentials. No account endpoint or external network request is made.

`recordedContext` is either `null` or `{source: "codex_token_count", usedTokens, limitTokens, recordedAt, freshness}`. `usedTokens` comes directly from `info.last_token_usage.total_tokens`; `limitTokens` comes from `info.model_context_window`. Codex itself uses the last response's token usage for its context percentage. The cumulative `total_token_usage` is never substituted, and lazysh does not reproduce Codex's baseline-adjusted percentage or invent remaining tokens. A later model change, compaction, input or fork can make this last recorded response measurement obsolete. An event with unavailable `info` clears recorded context.

`providerWindows` contains at most 16 entries from the last eight distinct limit IDs in the inspected window. Each entry has `provider: "codex"`, `accountId: null`, nullable `limitId`, `kind: "primary" | "secondary"`, recorded `usedPercent` (0–100), nullable `windowMinutes`, nullable RFC3339 `resetsAt`, `recordedAt`, and `freshness`. Durations and reset times come from the record; five-hour/weekly windows and account identity are never assumed. The newest snapshot for an ID replaces both windows for that ID, including removal of unavailable windows. A token-count event with unavailable `rate_limits` clears the window list. Older snapshots under other limit IDs remain separately labeled records rather than being added together.

Codex can repeat cached rate-limit snapshots in later token-count events. Their event timestamp establishes **recording time**, not the time the provider was queried, and it does not prove the authenticated account is unchanged. The UI explicitly labels account identity unknown. Records older than 15 minutes or whose recorded reset has passed are stale; missing/future recording times have unknown freshness. The client ages displayed metadata without fetching it again. A passed reset never produces a new allowance or zero usage automatically. Per-event counters may also repeat during rate-limit-only updates and are never summed.

Primary-source evidence is pinned to OpenAI Codex commit `970111f6cb62cc02fe36a82ea7d71b37a2889c97`, inspected 2026-10-25: [TokenCountEvent, TokenUsageInfo, RateLimitSnapshot and window field semantics](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/protocol/src/protocol.rs), [record envelope](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/history/src/lib.rs), [token-count persistence policy](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/rollout/src/policy.rs), [cached token/rate-limit event emission](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/core/src/session/mod.rs), and [the TUI's last-response context calculation](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/tui/src/chatwidget.rs). Tests create independent native JSONL fixtures in temporary directories. No developer/account rollout was inspected; live account accuracy and installed-version behavior remain unverified.

Supported counters depend on the selected adapter: Claude, Pi, OMP, jcode, current OpenCode projections and Codex token-count events can carry recorded request counters; Copilot's persisted message may carry only output tokens. Other supported transcript formats can legitimately produce no samples. Other providers' windows, account-bound live usage, current runtime context, provider quota APIs, opt-in background collection, nested-agent settings and independent companion settings remain [issue #18](https://github.com/mihazs/lazysh/issues/18) acceptance work.

Native Cargo tests cover duplicate/streaming counters, unknown versus zero, stale/future/undated reports, numeric bounds, cursor preservation, bounded samples and absence of prompt retention or state writes. Vitest covers protocol validation, explicit collection, stale labels, opaque pagination and discarding results from an old SSH session. These checks verify recorded-data handling; they do not validate an account's live usage or provider limits.
