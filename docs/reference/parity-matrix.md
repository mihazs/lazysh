# Reference-client parity matrix

Audit date: 2026-11-06 (verification re-audit; first audit 2026-11-04 at `aa1e2f34`). Source: `main` at `aea6aab2`; CI evidence from `main` runs up to `358c584f` (the `aea6aab2` run had not started when the re-audit closed). Scope: Android and desktop (Linux and Windows; macOS only where CI evidence exists). iOS appears only to justify `n/a`.

This matrix splits the rows of the [Behavior checklist and Agent coverage tables](../reference-evidence.md#behavior-checklist) into concrete sub-behaviors and states, per platform, whether lazysh implements each one and whether an automated test of observable behavior proves it on that platform. It is an audit snapshot, not a release claim. Re-audit after a change instead of editing one cell from memory. The reference product is called "the reference client" throughout, as in the evidence catalog.

## Status definitions

| Status | Meaning |
| --- | --- |
| `verified` | Implemented, and an automated observable-behavior test on that platform runs in a CI job and passed on `main` in the audited window (see [CI evidence](#ci-evidence)). Accepted tests: Android emulator instrumentation or an Android runtime harness, the Linux native GUI suite, a real-runtime Rust integration test, or Playwright in the matching project (`phone` for Android-shaped UI, `desktop` for desktop UI) when the behavior is purely web UI. |
| `implemented` | Code exists and is reachable from the UI on that platform, but platform verification is missing or only unit-level/mocked: Vitest/jsdom, Playwright against the mocked native bridge for a native behavior, Rust tests with in-process fakes, an `#[ignore]` test that no CI job runs, a test that only runs on macOS, or a native case that is currently red. |
| `partial` | Some of the behavior exists; the Missing column says exactly what is absent. |
| `missing` | Not implemented, or not reachable on that platform. |
| `n/a` | Platform-specific on the reference client too (for example iOS-only surfaces or desktop-only launch arguments); the reason is given. |

Reading rules:

- **Desktop** `verified` means Linux unless the cell names Windows. Windows has no SSH GUI test, so a Windows-only gap is not repeated in every row. It is tracked once in [Gaps](#gaps) (#492, #457).
- Playwright serves the Vite UI with a mocked native bridge (`apps/client/e2e/fixtures/nativeBridge.ts`) in Chromium. It never verifies SSH, transports, keystores, biometrics, push, files or other native effects.
- Abbreviations: `NWT` = `apps/client/src-tauri/gen/android/app/src/androidTest/java/app/lazysh/client/NativeWorkspaceTest.kt`; `ssh.spec` = `apps/client/native-e2e/ssh.spec.ts`; `TJF` = `apps/client/src-tauri/src/tmux_jump_fixture.rs`; `HGF` = `apps/client/src-tauri/src/herdr_guard_fixture.rs`; `MX` = `apps/client/src-tauri/src/multiplexer.rs`; `MP` = `apps/client/src/MultiplexerPanel.tsx`; `TP` = `apps/client/src/TerminalPane.tsx`; `PP` = `apps/client/src/PreferencesPanel.tsx`; `prefs` = `apps/client/src/preferences.ts`; `SS` = `apps/client/e2e/simple-shortcuts.spec.ts`; `CPF` = `apps/client/src-tauri/src/ssh/tests/connection_parity_fixture.rs`; `src-tauri` = `apps/client/src-tauri/src`. Other paths are repository-relative.
- Job names: `NAR` = `native-android-runtime`, `NAA` = `native-android-auxiliary`, `NAB` = `native-android-biometric`, `NAH` = `native-android-herdr-navigation`, `NAT` = `native-android-tmux`, `NAZ` = `native-android-zellij`, `NANT` = `native-android-ntfy`, `NL` = `native-linux`, `NLR` = `native-linux-runtimes`, `ND` = `native-desktop`, `NWL` = `native-windows-linux-host`, `PW` = Playwright in the `client` job (both projects unless marked).
- Android instrumentation suites are named as the `reports/androidTests/<suite>` directory of the job's results artifact (for example `NAR ssh-ui`, `NAR connected`). A cell promoted by the 2026-11-06 re-audit cites the run in the [CI evidence](#ci-evidence) table that proved it.

### Windows client: the exact limitation

`NDW` runs `cargo test --locked -p lazysh --lib -- multiplexer:: zellij:: herdr:: herdr_create:: tmux_jump::` (step "Exercise multiplexer version gates, command building and tree parsing"). Those are the non-ignored unit tests: the version table, command and argv building, discovery-script and tree parsing, and the pure Jump To parser.

The real-runtime cases that existed before #1747 are `#[ignore]` Rust tests (`bun run test:tmux`, `bun run test:multiplexers`) and the Android and Linux GUI suites. Each starts an owned loopback OpenSSH server and the pinned Linux multiplexer binaries on the machine running the test, and the windows-latest runner provides neither a Linux host nor the Linux multiplexer binaries.

[#1747](https://github.com/mihazs/lazysh/issues/1747) provides the host inside the runner. `NWL` starts an Ubuntu 24.04 WSL 2 distribution (real Linux kernel 6.18.54.1-microsoft-standard-WSL2 on the 20261111.331.1 image; WSL 1 also starts but emulates the kernel) with an unprivileged OpenSSH server on its loopback, tmux 3.4 from apt, the checksum-verified Zellij 0.45.1 and the same-run stock Herdr, and WSL 2 forwards that loopback port to the Windows loopback. The Rust client then runs natively on Windows against it: discovery with versions and support, and for each multiplexer attach, the tree and actions, through the product commands (`multiplexer_tree`, `tmux_action`, `attach_multiplexer`, `zellij_tabs`, `zellij_action`, `multiplexer_sessions`, `herdr_tree`, `herdr_action`). [How it works and its limits](../multiplexers.md#a-windows-client-against-a-linux-host).

The four cases passed on a hosted windows-latest probe run (43770703756, branch `ci/probe-windows-linux-host-cases`). `NWL` runs only on pushes to `main`, like `NDW`, and its first `main` run is still to come, so every Windows cell below stays `implemented` and names its `NWL` case. The probe branch also carried the one-line compile fix that later merged as #1906. When `NWL` has passed on `main`, the cells it proves become `verified` and its `continue-on-error` is removed.

What `NWL` does not prove, whatever its result: Jump To control mode, confirmed input and the guarded Herdr binding (their fixtures start local Unix processes and are not ported), Mosh, the Windows GUI, a remote rather than same-machine host, and a Windows OpenSSH host (out of scope: discovery returns `unsupported_host_shell`).
