# Optional guarded Herdr input

This owned extension targets the pinned Herdr 0.9.3 source import. Its implementation is tracked in [#283](https://github.com/mihazs/lazysh/issues/283), under [#268](https://github.com/mihazs/lazysh/issues/268). It is not a stock Herdr capability, an enabled lazysh Chat feature, or agent identity evidence.

## Authority and acquisition

An explicitly requested machine attachment registers an OS-random 256-bit client nonce on its exact endpoint connection. The server issues a fresh, independent 256-bit single-use claim ticket only in that connection's acknowledgement; a client-chosen value is never itself an external preparation credential. Re-registering an old client nonce cannot recreate a spent claim ticket. Acknowledgement precedes any terminal initialization, geometry-probe output or pane rendering. One bounded initial frame carries the ticket over the owning SSH exec stream. A retained native actor consumes this frame privately before forwarding display bytes. It must never scan later pane output for a ticket. A public client ID, current focus, pane title or transcript filename cannot substitute for this join.

A private claim consumes the ticket once and returns a connection-lifetime ownership credential. A lost or uncertain claim never permits replay or an automatic replacement attachment. The retained native actor uses that credential only for explicit preparation of a binding to the original transport client, random boot identity and exact nonfallback workspace/tab/pane/terminal/viewport. The caller cannot nominate another client. Protocol tickets, ownership credentials and remote receipts remain backend-only; neither those values nor terminal input payloads may enter argv, environment, logs or persistent storage. Ordinary local Chat draft text may live in frontend state. A native adapter may expose separate local confirmation IDs, never the protocol credentials. Guarded requests use bounded stdin/socket JSON. This is not an isolation boundary against a compromised authenticated host or hostile same-user processes with access to its server socket.

Registration expires unused after 30 seconds. Claimed ownership ends on original cancellation, explicit revocation or disconnect. A binding expires after 60 seconds. Preparation numbers are strictly increasing positive integers up to 2^53-1; gaps are allowed, but delayed or replayed numbers cannot overwrite newer state. An explicit new preparation retires the preceding binding without reconnecting or renewing original authority. Stale release and cancellation affect only their matching preparation. There is one binding per original client, at most 64 total, and one pending operation per binding. Positive operation numbers must match the exact next value and remain at most 2^53-1. They are consumed before work. A challenge expires after two seconds. Input failure or uncertainty retires that binding; loss of original ownership retires all authority. There is no queue, automatic retry, renewal, recovery registration or replay. Repreparation is an explicit user action only.

## Two cutoffs

The original client handles the challenge in one event-loop turn. Before an immediate commit on that exact endpoint it verifies endpoint/generation, logical active surface, Terminal mode, no copy/search/overlay/popup/selection/pending activation, and coherent target/snapshot/viewport. The server independently verifies the authoritative commit reader, random boot, original client and exact current target immediately before taking pending state and enqueueing one combined payload.

Client-local eligibility is true **at commit**. Server-owned identity is true **at enqueue**. A client mode change processed before the challenge rejects input. A server target change before enqueue rejects input. A later client mode change cannot recall a committed operation and cannot redirect its fixed target. Physical keys not yet processed do not have a cross-process wall-clock order. An acknowledgement means queue admission, not application receipt or execution. Observed pre-commit cancellation withdraws pending work; after the dispatch cutoff, closure cannot promise recall.

## Bounded input and compatibility

Send accepts nonempty text up to 4096 UTF-8 bytes. LF and TAB are permitted; all other control characters and Unicode U+2028/U+2029 are rejected, matching confirmed tmux Chat. Herdr's existing target-runtime bracketed-paste behavior encodes multiline/TAB text. Encoded text and the final CR are admitted together once. Request-stop sends fixed Escape. Request envelopes are at most 32 KiB. No arbitrary key sequence or agent spawn is supported.

Capability absence, unavailable entropy or uncertain local state fails closed. OS entropy uses the explicitly pinned, already-locked portable getrandom 0.3.4 dependency. Platform support remains unverified until exercised; unavailable entropy retains stock attachment and Stage/terminal fallback. Guarded machine startup uses one absolute receive deadline across welcome/registration, rejects unsupported receive-timeout transports, and excludes saved-catalog loading/watch/application and supervisor startup. It rejects federation, recovery and direct-terminal mode rather than silently acquiring a different client. No user host is installed or changed.

## Source and verification

Owned modules and tests here remain in the strict duplication scan. Thin upstream integration files retain Apache-2.0 notices, identify modifications, and lose their unchanged-vendor exclusions. The original source manifest is not rewritten. Optional builds use a source-verified external copy preserving these sibling paths and the shared `common/src/hex_digest.rs` and `common/src/guarded_target.rs` validators, since Zig-generated dependency directories cannot enter the project tree.

Native Cargo tests must use actual client/server paths and owned PTYs: competing tickets and clients, two servers with overlapping IDs, wrong/late/duplicate commits, state changes across both cutoffs, exact bytes and target isolation, disconnect/expiry cleanup, no replay, no secret Debug output and stock compatibility. Passing pure state tests alone does not establish that integration. The native lazysh SSH/lease/source adapter is tracked in [#297](https://github.com/mihazs/lazysh/issues/297); frontend availability, provider behavior and physical GUI acceptance remain separate work. Its connection-owned actor claims only the initial private frame before publishing display output, with a three-second absolute frame/RPC deadline and the existing bounded display-output credit window. Preparations and inputs retain their original access lease and complete transcript source; unlocking permits only a new explicit inspection and confirmation on the same still-owned connection. The validation-only invalid-preparation probe is an availability hint, never authority, and guarded startup failure never falls back to an ordinary attachment.
