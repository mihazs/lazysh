# lazysh ET transport

A bounded Rust library for the released Eternal Terminal 7.0.0 protocol (wire version 6). This package runs in-process and does not launch a local SSH or ET client. The caller performs a fresh bootstrap over its already host-key-verified SSH connection, then passes the bounded `IDPASSKEY:` output to `SessionSecret::from_bootstrap`.

`Client::connect(endpoint, secret, cols, rows).await` initializes the transport. `client.control()` returns a clonable controller with `send`, `resize`, and `reconnect` operations. Drain `client.next_event().await` concurrently to receive terminal `Output`, `Disconnected`, `Reconnected`, or `Failed` events. `send` succeeds when the input is accepted into the bounded transport; it does not certify remote execution. `close().await` cancels I/O even when output is not being consumed. Dropping the client also signals cancellation.

Network reconnect is explicit so the application owns retry timing and status. It preserves exact encrypted packet history and nonce state. Cold session restoration is intentionally unavailable: a new connection receiving returning-client status fails before encrypting anything. After a process restart, perform a fresh SSH bootstrap and reattach the durable multiplexer instead. Advertised challenge/reset handshakes are rejected until implemented and independently verified.

The client sends keepalive probes every five seconds. If no complete authenticated peer packet arrives for 15 seconds, it closes the socket and emits one `Disconnected` event, including when local TCP writes still succeed. Partial frames do not extend that deadline. If output delivery remains blocked for five seconds, the client deliberately closes TCP, retains the already authenticated packet, and delivers `Disconnected` after those bytes drain. The caller can then recover through the existing sequence/replay protocol. A long hidden-consumer pause therefore does not claim a live socket; server history exhaustion still fails explicitly. Dropped input/resize callers are skipped before queued commands are dispatched, without claiming to retract bytes already sent.

Bounds: 64 KiB bootstrap output, 64 KiB per input operation, 1 MiB interactive frames, 8 MiB setup/catch-up frames, 4096 catch-up packets, 8 MiB retained outbound ciphertext and 1 MiB disconnected input. Sixteen output chunks of at most 16 KiB and 32 queued input/control operations bound channels. Terminal dimensions are 1–1000 cells per axis. Required history outside these bounds fails explicitly; it is never silently discarded during disconnected input or replaced with fresh crypto counters. Retained connected history is bounded, so sufficiently long replay gaps require a fresh session.

The crate belongs to the root Cargo/Bun workspace and has no Tauri dependency or OS shell requirement. The app bootstraps it through verified SSH, then retains that SSH connection for files and host tools. The app integration reconnects the in-memory ET session after network loss with a bounded retry delay; cold launches require a fresh bootstrap. Only the optional interoperability tests start official host-side ET fixtures and ordinary host terminal commands.

Run unit tests with `cargo test --manifest-path packages/et-transport/Cargo.toml --locked`. Run the official-server integration tests with `ET_SERVER_BIN=/absolute/path/etserver ET_TERMINAL_BIN=/absolute/path/etterminal cargo test --manifest-path packages/et-transport/Cargo.toml --locked --test official -- --ignored`. They use temporary loopback ports, a private FIFO, isolated environment/log directories and cleanup of only their own helper processes. They cover executed UTF-8 output, resize, ordered offline input, mid-frame interruption/recovery, a 16-second blocked-consumer pause with exact 512 KiB replay, wrong-secret refusal and stalled-consumer cancellation. They do not test the caller's SSH bootstrap or modify a running ET service.

Actual Android/iOS lifecycle, roaming, cold-launch UX and energy use still require acceptance tests. The pure transport compiled for Android ARM64 and iOS ARM64 during development; those checks do not establish device behavior.
